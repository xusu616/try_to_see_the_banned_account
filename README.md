# GitHub 资料卡验证

在[在线验证页面](https://xusu616.github.io/try_to_see_the_banned_account/)输入 GitHub 用户名，查询结果显示在搜索框下的小资料卡中。优先读取已有核验记录，未收录时再读取 GitHub 公开资料；这两种查询均无需提交 Issue。下方“英灵殿”单独展示主页返回 404 且资料卡核验成功的账号。

公开资料和已有记录均未找到时，页面才提供“前往 GitHub 提交核验”。后台先匿名访问 `https://github.com/<用户名>`，只有原始地址明确返回 HTTP 404 才继续核验 Release 资料卡。返回 200 或重定向的账号不加入英灵殿，也不会修改 Release；正常可见账号仍可在顶栏显示公开资料。网络失败、403、429 和服务端错误会明确报告读取失败。404 本身不代表账号一定被封禁。

通过主页检查后，先从 Release 记录定位已有用户名，再展开对应 Contributors 卡片，缺失时才加入 `@提及`。每个资料卡 Release 最多分配 6 个账号；第 7 个新账号使用下一个补丁版本，例如 `v0.1.1` → `v0.1.2`。本次新增的预约在核验失败时回收，已有成员和原始说明保留；新建的空批次可供后续请求复用。用户名不区分大小写，已有账号复用原位置；已占用的 Tag 和无关 Release 不会被覆盖。资料卡批次不设置为 Latest，以保留 CLI 下载入口。每条结果和每张卡片都保留其实际所在的 Release 链接。

只有提交核验请求需要登录 GitHub。GitHub Pages 托管页面，Actions 使用运行时的仓库权限处理请求。普通访客可以打开已完成的请求链接查看结果。

## 下载和运行

从 [GitHub Releases](https://github.com/xusu616/try_to_see_the_banned_account/releases/latest) 下载 `find-profile-cards.pyz`。需要 Python 3.9 或更新版本，直接运行即可。

```powershell
python -X utf8 .\find-profile-cards.pyz rD227 xusu616/android_kernel_xiaomi_markw-4.9
```

扫描多个仓库时可以继续追加 `owner/repo` 或完整页面链接。`--starred <用户名>` 会加入该用户公开 Star 的仓库，`--max-tags <数量>` 控制每个仓库的检查范围。

```powershell
python -X utf8 .\find-profile-cards.pyz rD227 --starred xusu616 --max-tags 10
```

打开生成的 `profile-card-links.html`，在来源页悬浮对应署名即可查看 GitHub 资料卡。

## 验证流程

1. 点击“查询资料卡”：显示当前账号的小资料卡，正常公开账号不会被当作查询失败。
2. 点击“查看 GitHub 主页”：打开正常账号主页。核验卡则提供“查看 Release 来源”和“查看查询请求”，分别跳转到实际来源和原 Issue。
3. 仅在未查到资料时提供“前往 GitHub 提交核验”和“检查提交结果”。普通点击提交链接后开始等待；通过中键或右键在新标签页提交的，也可以返回点击“检查提交结果”。检查始终针对同一个请求，不会新建请求。
4. 找到请求后，“继续等待核验结果”继续读取同一个请求。复制结果和重新核验按钮已移除，维护者仍可通过 Actions 手动刷新既有请求。

搜索框、本次查询状态和小资料卡位于顶栏。下方“英灵殿”只收录 `github-actions[bot]` 明确返回 `verified`、与原查询请求匹配、且主页确认返回 HTTP 404 的结果；同一账号保留最近一次成功核验，每页最多显示 6 个，可在页面底部切换页码。确认尚未发布的新结果先显示在前面的分页，已发布账号保留在原静态分页，读取旧请求不会让账号重复出现在其他页。工作流成功后自动更新 Pages 中的公共列表。缺少主页状态的旧成功结果可以在顶栏查看，但不会加入英灵殿。旧的非 404 排除结果会读取公开资料，不再要求用户重复发起查询。

简介通过 `textContent` 保留原始换行，也会把字面 `\n`、`\r\n` 显示为换行。首次生成索引时会重新读取旧记录对应的已有贡献者卡片，恢复被旧版 `innerText` 压成空格的换行，迁移过程不会修改 Release。

Pages 构建使用 SQLite 的不区分大小写用户名主键和核验时间索引，只保存每个账号的最新成功结果。数据库通过 Actions 缓存复用，后续按同步时间游标增量读取新评论；首次构建或缓存丢失时从公开记录重建。请求内容被编辑而失效时，记录诊断并跳过对应结果，其他合法结果继续同步；网络故障仍会回滚本批同步。请求 ID 统一使用 UUID v4，旧缓存仅迁移不符合该规则的记录，保留同步游标和合规历史。入库时再次检查主页，每批同一账号只检查一次；历史记录缺少 404 证据时也必须通过检查。重新核验发现账号主页不再返回 404 时，会移除对应记录和导出的旧文件。

页面加载只获取小型元数据和当前页 6 张卡片；用户名查询直接读取对应 JSON 文件，已访问页在当前会话复用，不在浏览器扫描全部 Issue 或评论。索引、分页和单用户文件共享本次导出的标识，浏览器发现版本不一致时刷新列表，避免旧分页与新资料混用。数据库只在构建时使用，Pages 发布物不包含 SQLite 文件。公开列表保存核验时的状态，账号之后恢复可见时，需重新核验才能更新；不会在每次访问时扫描所有账号。浏览器收到排除结果后会立即隐藏该卡片，数量和分页等待下一次发布更新。

GitHub Actions 排队和页面更新需要时间，提交核验后页面会持续检查进度。限流、网络失败或资料卡暂未出现时，页面会显示实际状态。后台只接受格式有效的用户名和请求编号，在固定仓库分配资料卡 Release，结果评论由 `github-actions[bot]` 发布。

## 本地构建

回归测试使用 Python 和 Node.js 的内置测试工具：

```powershell
python -B -m unittest discover -s tests
node --test tests/test_site_app.cjs
```

```powershell
python scripts/build_pages.py --output dist
python -m http.server 8765 --bind 127.0.0.1 --directory dist
```

访问 `http://127.0.0.1:8765/` 即可预览。`python scripts/package_tool.py --output dist-tool` 会生成工具与 SHA-256 校验文件。推送版本 Tag 后，Release 工作流会重新打包并发布对应版本。

直接用浏览器打开 `site/index.html` 时，会从已发布网站读取公开账号列表；浏览器无法通过 `file://` 读取相邻的 JSON 文件。通过 HTTP 访问构建目录时，读取该目录的账号数据，本地未同步数据库时显示空列表。

构建后的 HTML 引用带内容指纹的 CSS 和 JS 文件，避免浏览器或 CDN 将新版页面与旧版资源混用。账号列表读取失败时会结束加载并显示重读按钮；重读会同时刷新列表元数据和分页缓存。
